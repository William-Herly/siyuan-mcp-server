# 开发与打包

## 开源维护原则

本项目面向外部用户和贡献者维护。实现、示例和操作流程应能在其他人的环境中理解和复现，不能依赖维护者的个人机器或聊天上下文。以下原则适用于代码、结构调整、文档和发布工作；Agent 的执行入口见根目录 [AGENTS.md](../AGENTS.md)。

- **兼容性**：MCP 工具名、schema、返回语义、profile、环境变量与 npm 启动入口都是用户接口。结构重构应保持这些接口稳定；需要破坏性变更时，说明影响、版本安排、迁移步骤和验证范围。内部源码路径调整也应检查仓库脚本、测试和文档引用。
- **可复现与跨平台**：通用流程兼顾 Windows、macOS 和 Linux；平台专用脚本明确标注适用范围。使用可替换的示例路径和合成数据，避免硬编码个人账户或实际工作空间。环境要求以包配置和已验证结果为依据，不能把单平台通过写成全平台通过。
- **隐私与公开内容**：代码、Issue 示例、文档和发布包不包含凭据、真实笔记、个人工作空间信息或未经审查的日志。忽略目录不等于脱敏；引用诊断材料前仍需检查内容。公开结论描述项目行为与适用条件，避免依赖私人对话才能理解。
- **依赖与许可证**：保留现有许可证、版权声明和所需的第三方来源说明。引入代码、素材或依赖时，检查其许可与分发要求、运行环境和维护成本，记录必要依据并同步锁文件；避免为小型重构引入无实际必要的新依赖或工具链。
- **审阅与文档**：重构、功能修改和权限语义变更分别组织，控制每次改动范围。说明修改原因、用户可见影响和验证结果。重要维护规则进入受版本控制的文档；同一事实维护一处，其他文档链接到权威说明。
- **验证与发布**：区分模拟测试、内存 MCP 协议测试、真实 CLI 测试和宿主隔离验证。只报告实际执行的检查；历史通过不能替代当前验证。发布前检查包内容、入口和迁移说明，本地构建或打包成功不代表已经对外发布。

## 本地检查

```bash
npm ci
npm run typecheck
npm test
npm run build
```

`typecheck` 检查源码、TypeScript 测试和 Vitest 配置，不产生输出。`build` 清理 `dist/` 后编译 `src/`，避免移动或删除源码后残留旧 JavaScript。`dist/index.js` 继续作为 npm 可执行入口，现有 MCP 客户端配置无需修改。

服务运行时的声明下限仍为 Node 18；贡献者完整检查推荐 Node 24，最低使用 Node 22.13+。Vitest 自身不支持 Node 18，生成查询的内存 SQLite 测试也需要较新的 Node。旧开发环境跳过 SQLite 用例不等于完整验证通过；单一版本的检查不证明所有声明运行版本和平台都已验证。

开发可使用 `npm run dev`；构建后使用 `npm start`。Windows 启动辅助位于 `scripts/`。

## 目录与产物

| 目录 | 用途 | 管理方式 |
| --- | --- | --- |
| `src/`、`tests/`、`scripts/` | 源码、维护测试与脚本 | 提交 Git |
| `docs/` | 用户说明、当前架构与开发指南 | 提交 Git |
| `notes/` | 本地方案、草稿、过程材料 | 忽略；长期维护规则整理进公开文档 |
| `notes/testing/` | 测试结论、阶段验收、历史验证记录 | 忽略；保留日期与适用范围，不随包发布 |
| `dist/` | TypeScript 编译输出 | 忽略；每次构建清理 |
| `artifacts/` | 可分发 `.tgz` 包 | 忽略；构建清理不删除 |
| `.siyuan-mcp/` | 运行日志、原始测试报告 | 忽略；不随包发布 |

保留 `dist/` 的名称。它已被 `main`、`bin`、启动脚本和 MCP 配置引用，改名没有实际收益。发布包与编译文件具有不同保留周期，因此新增 `artifacts/`，不混入 `dist/`。

## 生成发布包

```bash
npm run pack
```

该命令先通过 npm 的 `prepack` 生命周期运行类型检查、干净构建和测试，再创建 `artifacts/` 并打包。内部的 `npm pack --ignore-scripts --pack-destination artifacts` 避免嵌套调用重复执行同一套检查。包名来自 `package.json` 的名称和版本。重复打包同一版本会覆盖同名文件，需要保留旧结果时先归档或更新版本。

直接运行 `npm pack` 仍遵循 npm 默认行为，在当前目录生成包；仓库约定使用 `npm run pack`。打包是本地产物生成，不会执行 npm 发布或全局安装。

发布白名单由 `package.json.files` 管理，包含 `dist/`、公开文档、AGENTS.md、README 和 LICENSE，以及 npm 自动包含的包元数据。AGENTS.md 随包保留，确保公开文档中的维护约定链接可用。源码测试、本地过程记录、运行数据和 `artifacts/` 不进入包。

真实 CLI 测试仍由隔离门禁阻止，不能将发布包生成成功理解为真实集成验证通过。当前状态和恢复条件以[测试指南](testing.md)为准。

## 模块维护

模块职责和依赖方向以[架构文档](architecture.md)为准。测试从被测模块直接导入，避免新增统一转导出所有内部函数的入口。新增测试按纯函数/模拟 CLI 或工具行为归入 `unit/`、`behavior/`；仅真实思源进程测试放入 `integration/`，不得绕过隔离门禁。

工具参数以[工具参考](tool-coverage.md)为准，权限与失败语义以[写入保护](safety.md)为准；README 提供使用入口。逐次测试结论与历史报告放在 `notes/testing/`；公开测试指南只维护测试方法、覆盖范围和当前限制，不链接本地过程文件。
